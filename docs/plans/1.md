# Ленивые `Context.code_before` и `Context.code_after`

## Summary

Добавить в замороженный `Context` два независимо и лениво вычисляемых свойства:

```python
context.code_before: str
context.code_after: str
```

Текст ноды определяется как точный contextual source-span по `WhitespaceInclusivePositionProvider`:

```python
context.code_before + node_source_span + context.code_after == context.source
```

Первым изменением репозитория сохранить этот план в `docs/plans/1.md`.

## Публичный API

Обратную совместимость старого конструктора не сохранять:

```python
@dataclass(frozen=True, repr=False)
class Context:
    coordinate: Coordinate
    comment: Optional[str]
    source: str
    node_range: CodeRange
    meta: Optional[Dict[str, Any]] = None
```

- `source` и `node_range` обязательны, публичны и участвуют в equality.
- Не использовать `slots`, чтобы `cached_property` мог сохранять результат в `__dict__`.
- `code_before` и `code_after` реализовать независимыми `cached_property`.
- Frozen dataclass исключает устаревание кэша после переприсваивания source/range.
- Заморозка неглубокая: содержимое словаря `meta` остаётся изменяемым.
- Для `repr` использовать `printo.describe_call`, а не `reprlib` и не ручную конкатенацию.
- Передавать поля как keyword arguments в порядке конструктора и устанавливать `item_limit=80`. Ограничение применяется средствами `printo` к представлению каждого поля.
- `coordinate`, `comment`, `meta` и `get_metacodes()` сохраняют существующую семантику.

Установленная минимальная версия `printo==0.0.29` поддерживает `item_limit` в `describe_call`, но не в декораторе `repred`, поэтому для Context нужен собственный `__repr__`, делегирующий форматирование в `describe_call`.

## Передача `meta`

Текущую мутацию `context.meta` в `CallableWrapper` заменить на frozen-копию:

```python
callback_context = dataclasses.replace(
    context,
    meta=self.meta.copy() if isinstance(self.meta, dict) else None,
)
```

- Каждый двухаргументный callback получает отдельный Context и свежую копию wrapper meta.
- Мутация `meta` внутри одного callback не влияет на следующие вызовы, decorator dict, wrapper или исходный Context.
- При `wrapper.meta is None` callback получает `context.meta is None`, даже если у базового Context meta была непустой.
- Для одноаргументного callback поведение остаётся прежним.
- Не фиксировать тестами применение именно `dataclasses.replace` или identity передаваемого Context — это детали реализации.

## Границы и offsets

- `PositionProvider` продолжает формировать публичный `coordinate`.
- `WhitespaceInclusivePositionProvider` формирует обязательный `node_range`.
- `Bloodhound` и `SuperTransformer` получают исходный `Changer.source` и оба metadata ranges.
- В трансформере ranges брать у `original_node`.
- Все внутренние вызовы `Context(...)` перевести на новый обязательный конструктор.

Публичного whitespace-inclusive character-offset provider в LibCST нет:

- `ByteSpanPositionProvider` возвращает готовые байтовые offsets, но исключает owned whitespace;
- `WhitespaceInclusivePositionProvider` возвращает нужные границы только как `line`/`column`;
- `Module.code_for_node()` и поиск текста не дают универсально корректных границ.

Добавить внутреннее преобразование `CodePosition` в абсолютный символьный индекс, которое:

- поддерживает `\n`, `\r\n`, одиночный `\r` и их смешение;
- считает Python-символы, а не UTF-8-байты;
- работает для `line > 1` после Unicode и разных newline;
- поддерживает виртуальную EOF-позицию при отсутствии финального newline;
- поддерживает `start == end`;
- не копирует весь source и не строит список всех строк;
- учитывает начальные символы, которые LibCST исключает из codegen-позиций: BOM `U+FEFF` и валидный leading form-feed prefix;
- вызывается только при чтении соответствующего cached property.

## Правила тестирования

- Общие test-helper функции для проверки разбиения не создавать.
- Exact-ассерты дублировать непосредственно в каждом correctness-тесте.
- Ожидаемый node span задавать строковым литералом, а не вычислять production-helper’ом или `Module.code_for_node()`.
- Каждый correctness-тест напрямую проверяет:

```python
assert context.code_before == expected_before
assert context.node_range == expected_range
assert context.code_after == expected_after
assert (
    context.code_before
    + expected_node_source_span
    + context.code_after
    == context.source
)
```

- Каждый новый тест получает докстрингу с описанием контракта и значимых деталей сценария.
- Ленивость доказывать наблюдением реальных операций `source[...]`, а не только вызовов offset-helper.
- Локальный инструментальный класс внутри отдельного теста допустим; общим helper или fixture его не делать.

## Документация и проверка

README должен описывать:

- обязательные `source` и `node_range`;
- frozen-семантику Context;
- ленивость и кэширование;
- contextual source-span;
- отличие от `Module.code_for_node()`;
- дополнительную стоимость второго metadata provider;
- сохранение BOM и leading form-feed prefix;
- ограничение `repr` через `printo.describe_call(item_limit=80)`.

После реализации выполнить:

1. Полный `pytest`.
2. Coverage и branch coverage с существующим порогом 100%.
3. `ruff check cstvis tests`.
4. `mypy --strict cstvis` и `mypy tests`.
5. Проверить, что изменены только `docs/plans/1.md`, реализация, тесты и README; версию пакета и release-конфигурацию не менять.

## Assumptions

- Обратная совместимость старого конструктора намеренно не сохраняется.
- `Context` — frozen и не slotted.
- `meta` остаётся mutable dict, но каждый callback получает свежую копию wrapper meta.
- Before/after всегда относятся к исходному `Changer.source`.
- Общих test helpers не создаётся.
- Каждый correctness-тест напрямую проверяет before, range, явный node span, after и round-trip.
- Repr строится через `printo.describe_call` с `item_limit=80`.
